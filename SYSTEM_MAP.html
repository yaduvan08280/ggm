How the system works, who checks what, and what can break it

Every label below comes from the code in this folder. "Connected" means the app has the Portal connector, but it only takes effect once its three Script properties are pasted. Where an app is not connected yet, its old login still runs, as noted.

1System map

One login (the hub) in front of 8 Apps Script apps. Every app runs as itadmin@ and reads and writes Google Sheets directly. Five apps write the same Delegated task sheet.

① launch pass: signed with that app's secret, 90 s, single use ② hub → app: signed POST (provision · mode · counts · meta · listUsers) ③ app → hub: signed POST (verify a password · list users for "Assign to") unprotected writer

2Sign-in and tile tap: who verifies what

Read top to bottom. Every check is on a server: the phone is never trusted, it only carries tokens.

Own link, switch OFF (direct login)

  1. The app's login form sends username/phone + password to its own server.
  2. The app calls the hub: POST ?portal=1 · op verify, signed with its secret.
  3. The hub checks the signature, that the switch is OFF, the password (same lockout), and the Access ✓.
  4. The hub returns the claims → the app creates its own session ("D" token / direct).

Own link, switch ON

  1. No pass in the URL → the app shows "Open through GGM Portal".
  2. Its login form is refused (the app's PORTAL_ONLY = true, and the hub also refuses).
  3. Only sessions started from a launch pass are accepted on every request.
  4. Emergency: set PORTAL_ONLY = false in that app's Script properties.

4Background jobs (hub triggers)

Every minute: sync (portalMinuteJob)

  1. Retry the Portal-only switch for apps that did not confirm.
  2. For each connected app: build "wanted" per user from Users + Access + App Logins.
  3. Missing role / site / doer, or two users with the same id in an app → BLOCKED (not sent).
  4. Changed rows only → op provision (25 per call) → the app writes its own users / switches off.
  5. Results → Sync tab (written only if something changed) → Access "SYNC" column. Log trimmed.

Every 5 min: badges · daily: dropdowns

  1. Badges: op counts to each app, 15 users per call, in parallel → cache + Badges tab.
  2. Levanto: the hub reads "New Base" → Grade Alerts directly.
  3. Closing an app refreshes that one number (cache only).
  4. Daily 06:00: op meta → Lists tab (roles, sites, doer names) → Access dropdowns rebuilt.
  5. Sheet edit (onPortalEdit): hashes typed passwords, rebuilds Access on Users / Apps changes, clears the cache.

7Changes that can break the system

ChangeWhat breaksSafe way
Insert, delete or move a column in any app sheet (Master, Monthly Master, Users, FUEL DETAIL DRIVERS, Present Assets List…)Apps read and write by column position: data lands in the wrong column silently. Assets also uses fixed row ranges per site (rows 4–21, 25–39…)Only add columns at the far right. Never insert rows inside the Assets site blocks.
Rename a tab (Master, Users, Doer List, Leave, MM, Sessions, _AUTH…)The app can't find it; errors or empty screensNever rename; add new tabs instead.
Delete or change HUB_SECRET / PEPPER in the hubPEPPER: every password stops working. HUB_SECRET: everyone signed out.Never touch them. "Set up / repair tabs" only creates them if missing.
"Connect selected app" → NO (make a new secret) without pasting it into the appThat app's tiles, sync, badges and logins all failChoose YES (show existing) unless the secret leaked.
"New deployment" instead of "New version"New /exec URL: the hub's Apps tab, bookmarks and Telegram buttons point at old code (this is what happened with the Staff Dashboard: version 84 vs 83)Manage deployments → Edit → New version, always.
clasp push from a folder that is missing a file, or after editing in the browser editorA push replaces the whole project with the folder: files only in the editor are deleted (Jaipur's page was lost this way)Pull into a scratch folder first and compare; keep this folder as the only source.
Rename a person (Doer List, Master C, Users C, routine sheets)Staff / Newai / Tonk / Jaipur find tasks by name: their tasks disappear or match someone elseChange the name everywhere at once, and the Doer name in the hub Access grid.
Two hub users map to the same id in an app (same email, App Logins, doer)Sync blocks both rows (by design) until fixedCheck the Sync tab after adding people.
Add a status word (e.g. "Hold") in Master JThe task apps treat unknown words as PendingKeep to Pending / Review / Completed / Rejected / Week Shifted, or ask for the code to learn it.
Edit Access header rows 1–2 by hand, or reorder Users / Apps columnsThe hub reads app columns from those headers; wrong ticks or lost accessChange apps in the Apps tab; the grid rebuilds itself.
Portal-only ON while the hub is brokenNobody can open any appEmergency: PORTAL_ONLY = false in each app's Script properties.
itadmin@ loses access to a sheet, or the account is suspendedEvery app runs as itadmin@: everything stopsKeep itadmin@ as owner of all scripts and sheets.
Many users at onceGoogle allows ~30 scripts running at once per account (all apps share itadmin@); trigger runtime 6 h/dayRaise the badge interval if "too many simultaneous invocations" appears.
Task Delegation used alongside Main AdminNo login; clashing columns H, R/S; duplicate TK IDs; two doGets pick a page by file orderConnect it (sign-in, Given By, clean-up) or retire it in favour of Main Admin.
Google drops a cache entry earlySomeone has to sign in again or reopen the tileNothing to do; expected.
